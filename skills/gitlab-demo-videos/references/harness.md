# Harness reference (GitLab demo-video kit)

Paths are relative to the restored kit dir (the target of `scripts/setup.sh`).

Offline, synthetic-data demo videos of GitLab UI, rendered with **GitLab's own frontend code**
(Vue components + compiled stylesheets from a sparse checkout of `gitlab-org/gitlab` at the tag in
`gl-src.pin`, `v19.4.1-ee` when this skill was written) and recorded with Playwright. No GitLab instance,
no production data.

```
gl-src/            sparse checkout of gitlab-org/gitlab @ gl-src.pin (JS, stylesheets, views, helpers, lib/sidebars, ...)
app/               build project (Vite + Vue 2.7 + @gitlab/ui 137.2.0, same as GitLab 19.4)
  build/           build_css.mjs, tailwind.config.cjs, gen_pages.mjs, vite_plugin_graphql.mjs      (SHARED)
  src/shell/       reusable GitLab page shell                                                       (SHARED)
    layout.mjs       page HTML = layouts/application + _page + StaticPanelComponent (+ group/project/settings layouts)
    sidebar_data.mjs super_sidebar_context JSON: panels your_work | profile | group | project | admin
    contexts.mjs     the fictional org: USER (Alex Rivera @arivera), GROUPS, PROJECTS, path helpers
    haml.mjs         exact markup of HAML/ViewComponent pieces: settingsBlock, settingsSection, checkbox, button,
                     pageHeading, alert, flash, form, sprite, saveButton, helpLink
    boot.js          mounts GitLab's REAL super sidebar, top bar, breadcrumbs, settings panels, search settings,
                     Duo panel; installs mockBackend; exports mockBackend, demoState, createMockApolloClient
    mock_apollo.js   in-browser GraphQL "server" for an app's own Apollo client (resolvers by operationName)
    mock_backend.js  intercepts fetch + axios: GraphQL through GitLab's DEFAULT client and REST calls
  demos/<slug>/    ONE FOLDER PER DEMO - the only place a demo agent writes
  .build/<slug>/   generated pages + Vite output + Vite cache of that demo (disposable)
  public/assets/   compiled GitLab CSS (application, tailwind, fonts, every page_bundles_*.css), icons.svg
                   (generated by setup.sh, not stored in the skill)                                  (SHARED)
harness/           build.mjs, serve.mjs, record.mjs, narrated.mjs, check.mjs, shot.mjs, probe.mjs, cursor*.js,
                   caption_overlay.js, fake_date.js, browser.mjs                                     (SHARED)
narration/         local Kokoro TTS step: narrate.py, scripts/<slug>.json, .venv, models  (see narration.md)
tools/ffmpeg       symlink to the system ffmpeg, or to a static build from the imageio-ffmpeg wheel
out/<slug>/        results: <slug>.mp4, <slug>-preview.gif, <slug>-<mark>.png, marks.json, check/*.png
```

Reference demos: `app/demos/credits-dashboard` (personal GitLab Credits usage, profile panel, full scenario) and
`app/demos/shell-smoke` (group settings HAML form + flash, project settings, project AI > Triggers via sidebar,
mockBackend, admin panel, captions).

## Working rules

- **New demo = new folder `app/demos/<slug>/` + `narration/scripts/<slug>.json`.** The shared pieces
  (`app/src/shell/*`, `app/build/*`, `app/vite.config.mjs`, `harness/*`, `app/public/assets/*`, `package.json`)
  are configurable per page (see below). Edit them only for a kit-wide fix, and then re-run an existing demo
  (e.g. `credit-caps`) to make sure nothing regressed. If several agents work in parallel, only one owns shared files.
- Builds and recordings are per slug (`app/.build/<slug>/`, `out/<slug>/`, free port per run), so different demos can
  build at the same time - but see "Load" in [lessons.md](lessons.md) before recording more than two at once.
- `gl-src` is a **sparse, blobless** checkout: add paths with `git -C gl-src sparse-checkout add '/path/'`
  (non-cone patterns; retry if `index.lock` exists). Never `sparse-checkout set`/`disable`, never `git grep` /
  `git log -p` / `git checkout .` across the tree (each fetches every blob). If you add paths that a future restore
  needs, also append them to `gl-src.sparse-checkout` (the file setup.sh restores from). Already included: all of
  `app/assets/javascripts`, `ee/app/assets/javascripts`, stylesheets, `app/views`, `ee/app/views`, helpers,
  components, controllers, policies, `lib/sidebars`, `ee/lib/sidebars`, routes, feature flags,
  `ee/spec/frontend/usage_quotas`, `ee/spec/frontend/ai`, EE images, some `doc/` folders (Duo, DAP, subscriptions).
- To find the real source of a page: controller in `{ee/,}app/controllers`, view in `{ee/,}app/views/**.haml`,
  the `#js-...` mount point and its `index.js` in `{ee/,}app/assets/javascripts/**`, mock data shapes in
  `ee/spec/frontend/**/mock_data.js`, docs in `gl-src/doc/**`. Read GitLab source files directly from `gl-src`
  (they are already checked out); for a path outside the sparse set, add it first.
- npm deps already include vue-router 3.6.5, @gitlab/duo-ui, echarts, d3, yaml, cronstrue, jszip, ...
  If an import is still missing, install the exact version from `gl-src/package.json` with
  `npm install --legacy-peer-deps --save-exact <pkg>@<ver>` (in `app/`), copy the new `package.json` entry
  into the skill's `kit/app/package.json`, and avoid running two installs at once.
- Stylesheets: setup compiles every CE+EE page bundle (`app/public/assets/page_bundles_<name>.css`, e.g.
  `page_bundles_settings.css`, `page_bundles_group_edit.css`, `page_bundles_projects.css`). Tailwind was built
  from all GitLab sources, so classes copied from HAML/Vue exist. `npm run css` (in `app/`, 3-5 min) rebuilds all of
  it; for one missing utility just put a small `<style>` in the page's `headHtml`.

## Add a new demo

Create `app/demos/<slug>/` with:

| file | required | what |
|---|---|---|
| `pages.mjs` | yes | default export: array of page definitions (Node ESM) |
| `entry_*.js` | per Vue page | browser entry; **first line** `import '@demo/src/shell/boot';` then mount the real app |
| `scenario.mjs` | to record | `export const meta` + `export default async function run(ctx)` |
| `data.js` / `*.html` | optional | synthetic data, static HTML fragments |
| `rest.mjs` | optional | server-side answers for full-page form posts / navigations |
| `narration/scripts/<slug>.json` | for a voiceover | narration cues (lives outside the demo folder; one file per slug) |

Vite discovers the pages automatically; nothing shared needs editing.

### pages.mjs

```js
import { settingsBlock, checkbox, saveButton, form } from '../../src/shell/haml.mjs';
export default [
  {
    route: '/groups/acme-corp/-/settings/gitlab_credits_dashboard',  // :param and trailing * allowed; routes: [aliases]
    group: 'acme-corp',                 // or project: 'acme-corp/checkout-service' (group is derived)
    // panel: 'group' | 'project' | 'your_work' | 'profile' | 'admin'  (default: from project/group)
    activeMenuId: 'gitlab_credits_dashboard',   // sidebar item id (section expands automatically)
    title: ['GitLab Credits dashboard'],        // layout appends ['Settings' if settingsLayout], group/project, 'GitLab'
    crumbs: [{ text: 'GitLab Credits dashboard', href: '/groups/acme-corp/-/settings/gitlab_credits_dashboard' }],
    bodyPage: 'groups:settings:gitlab_credits_dashboard:index',   // controller path + action, like body[data-page]
    entry: 'entry_dashboard.js',                // relative to the demo folder; omit for static HTML pages
    content: '<div id="js-group-usage-billing-dashboard" data-namespace-path="acme-corp"></div>',
    gon: { features: { walletAgnosticCreditsDashboard: true, creditCapsUi: true } },
  },
];
```

Page fields (full list in `src/shell/layout.mjs`): `route`, `routes`, `name`, `title`, `panel`, `group`, `project`,
`activeMenuId`, `sidebar`, `crumbs`, `breadcrumbs` (full override), `settingsLayout` (adds `page_bundles/settings`
[+ `projects`] CSS and the "Search settings" box like `layouts/*_settings`), `searchSettings: false`, `bodyPage`,
`content`, `entry`, `pageStyles` (e.g. `['page_bundles_group_edit.css']`), `fluid`, `gon` (merged into
`window.gon`), `flash` (`{ notice: '...' }`), `duoPanel` (default on for group/project pages: the collapsed
GitLab Duo panel rail on the right, as GitLab.com shows it for a Duo user; `false` to hide), `saas` (default
true; false for admin = Self-Managed), `headHtml`, `user`.

`sidebar` options: `hide: [ids]`, `pins: [ids]` (defaults = Rails default pins), `transform: (items) => items`,
`duoFeaturesEnabled: false` (drops the AI section + Duo panel), `duoWorkflowEnabled: false` (drops AI > Sessions),
`plan: 'premium'` (drops Ultimate-only items), `activeSectionId`, `extra: {...}` (merged into data-sidebar).

Breadcrumbs start with the group chain (+ project) automatically; add the page's own crumbs with `crumbs`.

Other groups/projects: pass an object with the shape documented in `contexts.mjs` instead of a key.

### HAML-only pages (static HTML)

Build `content` from `haml.mjs` helpers so markup/classes match the ViewComponents; copy copy/labels from the
real `.html.haml` (+ locale strings). `settingsBlock({ heading, description, id, expanded, body })` is a real
expandable `section.settings` (expand/collapse and Search settings are wired by boot.js). Forms: wrap fields in
`form({ action, method: 'patch', body })` and answer the post in `rest.mjs`:

```js
export default {
  'PATCH /groups/acme-corp': () => ({ redirect: '/groups/acme-corp/-/edit#js-permissions-settings',
    flash: { notice: "Group 'Acme Corp' was successfully updated." } }),
};
```

The redirect renders the flash like `layouts/_flash`, the `#anchor` re-expands that section (settings_panels.js),
and field values persist across the round trip (`data-demo-persist`, sessionStorage). For other cross-page state
use `demoState.get/set` from `@demo/src/shell/boot`.

### Mocking GraphQL / REST in the browser

Two options; both live in your entry file:

1. **App builds its own Apollo client** (most `index.js` files: `new VueApollo({ defaultClient: createDefaultClient() })`):
   either replicate the app's `index.js` with `createMockApolloClient({ operationName: (variables) => data })`
   (as `credits-dashboard/entry_credits.js` does), or keep the real init untouched and register handlers:
2. **`mockBackend`** (installed by boot.js before anything mounts) answers GitLab's default client
   (`/api/graphql`, batched or not) and REST via `~/lib/utils/axios_utils` or `fetch`:

```js
import { mockBackend } from '@demo/src/shell/boot';
import { initDuoAgentsPlatformProjectPage } from 'ee/ai/duo_agents_platform/namespace/project'; // real init, unmodified
mockBackend.graphql({
  getAiFlowTriggers: (vars) => ({ project: { __typename: 'Project', id: 'gid://gitlab/Project/2001', aiFlowTriggers: {...} } }),
  updateAiFlowTrigger: ({ input }) => { state.active = input.active; return { aiFlowTriggerUpdate: { errors: [], aiFlowTrigger: {...} } }; },
});
mockBackend.rest({ 'PUT /api/v4/groups/:id': ({ params, body }) => ({ id: Number(params.id), ...body }) });
initDuoAgentsPlatformProjectPage();   // reads the #js-... mount point + data-* you put in page `content`
```

Handlers may be async and keep in-memory state so a mutation changes what the next query returns. Return
`{ status, data }` for non-200s; throw to return a GraphQL error. Use the spec mock data
(`ee/spec/frontend/**/mock_data.js`) as the shape reference and include `__typename`s. Unhandled operations
show up as `[mock-backend] graphql passthrough <name>` / `[mock-apollo] no resolver for <name>` in
`harness/shot.mjs` and `harness/check.mjs` output. Feature flags: `gon.features.<camelCase>` via the page `gon`.
Fake any LLM output with short static content.

Sidebar counts come from a default `getAsyncSuperSidebarData` handler (override by registering your own or with
`window.__demoSidebarCounts = { openMergeRequestsCount: 9 }` before boot). The Duo panel ships default answers for
its on-load queries; a demo that opens the chat must mock the chat's queries itself.

### Build, check, record

```sh
node harness/build.mjs <slug>                       # gen pages + vite build -> app/.build/<slug>/dist (~20s)
node harness/check.mjs <slug>                       # screenshot every concrete route to out/<slug>/check/, list errors + unmocked calls
node harness/shot.mjs <slug> <route> [out.png] [ms] # one screenshot with console output
node harness/probe.mjs <slug> <route> "<js expr>"   # evaluate JS on a page (find selectors/coordinates)
node harness/serve.mjs <slug> [port]                # browse manually
node harness/record.mjs <slug> [--no-build] [--keep-raw] [--capture=playwright] [--port=N] [--no-pace]
node harness/narrated.mjs <slug> [record.mjs options] [--voice=V --speed=S]   # narrated video, see "Narration" below
```

`scenario.mjs`:

```js
export const meta = {
  startRoute: '/groups/acme-corp/-/edit',
  demoTime: '2026-09-25T15:40:00-04:00',   // fixed demo clock (time keeps flowing from there)
  timezoneId: 'America/New_York',
  cursorStart: { x: 1400, y: 640 },
};
export default async function run({ page, cursor, pause, mark, caption, hideCaption, waitForIdle, goto, type }) {
  await caption('Settings > General');                        // small bottom caption; { step: 'Step 1' } adds a label
  await cursor.click(page.getByRole('heading', { name: 'Permissions and group features' }));
  await pause(900);
  mark('expanded');                                           // -> out/<slug>/<slug>-expanded.png
  await cursor.click(page.locator('#super-sidebar').getByRole('link', { name: 'GitLab Credits' }));
  await page.waitForURL('**/gitlab_credits_dashboard'); await waitForIdle(); await cursor.sync();
  await hideCaption();
}
```

Cursor: `cursor.click(locator, { dx, dy, ox, oy, duration, settle })`, `cursor.moveTo(locator)`,
`cursor.moveToPoint(x, y)`, `cursor.clickPoint(x, y)`, `cursor.point(locator)`, `cursor.sync()` after a navigation.
`goto(route)` navigates directly (use sparingly; prefer clicking the real sidebar). `type(locator, text)` types
visibly. Captions persist across navigations until `hideCaption()`. After a click that navigates, wait for the
*new* URL (a glob that also matches the current URL resolves immediately). On failure the recorder saves
`out/<slug>/error.png`.

Output: MP4 (H.264 CRF 17, 1920x1080, 30 fps) from CDP screencast frames, GIF preview, stills per `mark()`.
Verify with `tools/ffmpeg -i out/<slug>/<slug>.mp4` (duration / 1920x1080) and look at the stills.
The recorder sorts + dedupes screencast frames by capture timestamp (they arrive out of order after
navigations), timestamps `mark()` after the state has been painted, and keeps capturing until a frame from
after the last action has arrived, so video time = scenario wall time (the MP4 duration equals the
`duration` it prints) and the tail is never cut.

### Narration (voiceover + captions)

Per-demo convention - one script, `say()` calls in the scenario, one command:

1. **Script** `narration/scripts/<slug>.json` (voice `af_heart`, speed `1.0` unless there is a reason):
   ```json
   { "slug": "<slug>", "engine": "kokoro", "voice": "af_heart", "speed": 1.0,
     "cues": [
       { "id": "intro",    "text": "Here's how to check your own GitLab Credits usage." },
       { "id": "navigate", "text": "Open your avatar menu, choose Edit profile, then pick GitLab Credits in User settings." } ] }
   ```
   `id` is short kebab/camel text, unique in the file; `text` is what is spoken (and becomes the captions).
   No `start` needed: the recording decides when each line plays. (A cue may still carry `start` seconds
   or `{ "scene": "<mark>", "offset": s }` as a fallback; it is used only if the scenario never says it.)
2. **Scenario**: take `say` and `settle` from the context and call `say(id)` once per cue, in script order,
   at the moment the line should start:
   ```js
   export default async function run({ page, cursor, pause, mark, say, settle }) {
     await say('intro');                  // awaited: speak the whole line, then continue
     await settle(400);
     say('navigate');                     // not awaited: act while the line plays...
     await cursor.click(userMenu); await pause(900);
     await cursor.click(creditsLink); await page.waitForURL('**/gitlab_credits_dashboard');
     await settle(900);                   // ...then wait until it has been spoken (+0.3 s), at least 900 ms
     mark('dashboard');
   }
   ```
   - `say(id)` records the cue start (seconds from video t=0) and returns a promise that resolves when the
     line's audio ends (length from `out/<slug>/durations.json`). An unknown id throws.
   - `settle(minMs)` waits until the current line has finished plus a 0.3 s gap, and at least `minMs`.
     Put a `settle()` (or an awaited `say`) before every next `say()`; if a `say()` comes too early the
     recorder warns and queues the cue after the previous one, so lines never overlap.
   - After `run()` returns the recorder waits for the last line + 0.7 s, so the ending is never cut.
   - `say`/`settle` also pace a plain `record.mjs` run (lengths from `durations.json`, or estimated
     from the text if it has not been generated), so the silent and narrated cuts match. `--no-pace` disables them.
3. **Build it**: `node harness/narrated.mjs <slug>` (add `--no-build` to reuse the last build). It runs
   `narrate.py --durations-only` -> `record.mjs` -> `narrate.py` (about 2 min for a 50 s demo).
4. **Outputs** in `out/<slug>/`: `<slug>-narrated.mp4` (video stream copied bit for bit + AAC 48 kHz mono
   voiceover at -16 LUFS, no subtitle track), `<slug>.mp4` (same picture, silent), `<slug>.srt` +
   `<slug>.vtt` (sidecar captions), `cues.json` (`{ id: start s }` actually used), `durations.json`, stills,
   GIF. Placement report: `narration/work/<slug>/timing.json` (`warnings` must be empty).
5. **Verify**: `tools/ffmpeg -i out/<slug>/<slug>-narrated.mp4` shows one h264 + one aac stream;
   `tools/ffmpeg -i out/<slug>/<slug>-narrated.mp4 -map 0:a -af volumedetect -f null -` gives a mean around
   -18 dB (not -91); grab a frame in the middle of a few cues and check it shows what the line says.

Reference: `app/demos/credits-dashboard/scenario.mjs` + `narration/scripts/credits-dashboard.json`.

Notes: pages stay hidden until the Vue shell mounts (Chromium paint-holding keeps the previous page on screen),
which avoids the unstyled flash a slow local bundle would otherwise show. `fe_islands/*` (separately built Vue 3
islands such as duo_next) are stubbed. Named operation imports from `.graphql` files are supported.

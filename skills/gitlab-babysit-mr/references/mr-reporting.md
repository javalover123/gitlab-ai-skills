# MR Reporting — Resolved Discussion Thread

Post all reports inside a **single resolved discussion** so they stay collapsed and out of the way.

## First report: Create resolved discussion, then reply with report

Use `-R "$PROJECT_PATH"` on every call (the MR is addressed by `$MR_IID`).
Requires glab 1.101 or newer (`mr note list`/`resolve`, `create --reply`, `--resolvable`; the Duo note in lint-fix-delegation.md needs the same). `resolve` takes the MR first and the discussion ID last, despite what its `--help` USAGE line shows.

**Step 1**: Create a small discussion, look up its ID, and immediately resolve it.

```bash
PLACEHOLDER="Thread generated by \`/gitlab-babysit-mr\`"
glab mr note create "$MR_IID" -R "$PROJECT_PATH" -m "$PLACEHOLDER"

# `create` doesn't document returning the discussion ID, so read it back from
# the list (JSON is `null`, not `[]`, when empty, hence `// []`).
DISCUSSION_ID=$(glab mr note list "$MR_IID" -R "$PROJECT_PATH" -F json |
  jq -r --arg body "$PLACEHOLDER" \
    '[(. // [])[] | select(.notes[0].body == $body)] | last | .id')
[ -n "$DISCUSSION_ID" ] && [ "$DISCUSSION_ID" != null ] ||
  { echo "placeholder discussion not found" >&2; exit 1; }

# Resolve so it's collapsed (accepts the full ID or an 8+ char prefix)
glab mr note resolve "$MR_IID" "$DISCUSSION_ID" -R "$PROJECT_PATH"
```

**Step 2**: Post the actual report as a reply, then re-resolve the discussion (a reply to a resolved discussion leaves it resolved; re-resolving restores the state if someone unresolved it meanwhile).

```bash
glab mr note create "$MR_IID" -R "$PROJECT_PATH" --reply "$DISCUSSION_ID" -m "$(cat <<'COMMENT'
## Pipeline Babysitter Report

**Pipeline**: <pipeline_url> | **Status**: <pipeline_status> | **Commit**: `<pipeline_sha>`
**Action round**: 1 of 5

### Failed Jobs

**`<job_name>`** · stage: `<stage>`
- **Failure summary**: <1-2 line description from log>
- **Classification**: FLAKY | MASTER_BROKEN | LINT | COVERAGE | REAL_FAILURE | UNKNOWN
- **Known issue**: <URL or "none found">
- **Action taken**: <description or "none — requires manual fix">

_(repeat for each failed job)_

### Summary

| Classification | Jobs | Action |
|----------------|------|--------|
| Flaky | N | Retried (attempt M of 2) / pipeline retried |
| Master broken | N | Pipeline retried / linked issue |
| Lint | N | Auto-fixed and pushed |
| Coverage | N | Retried / requires manual fix |
| Real failure | N | **Requires manual fix** |
| Unknown | N | Retried once |

_Waiting for pipeline to finish before next check._

---
*Generated by `/babysit-mr`*
COMMENT
)"

# Re-resolve the discussion (replies leave it resolved; this restores the state if someone unresolved it)
glab mr note resolve "$MR_IID" "$DISCUSSION_ID" -R "$PROJECT_PATH"
```

## Subsequent reports: Reply to existing discussion

```bash
glab mr note create "$MR_IID" -R "$PROJECT_PATH" --reply "$DISCUSSION_ID" -m "<report body>"

# Re-resolve the discussion (replies leave it resolved; this restores the state if someone unresolved it)
glab mr note resolve "$MR_IID" "$DISCUSSION_ID" -R "$PROJECT_PATH"
```

Store `DISCUSSION_ID` across action rounds so all updates form a single thread.
